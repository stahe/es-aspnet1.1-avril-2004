    5. Gestión de la interfaz de usuario

    5.1. Introducción

    En la relación cliente-servidor en la web, el cliente envía información al servidor en forma de una cadena de parámetros [param1=val1&param2=val2&...]. En nuestros ejemplos anteriores, la mayoría de las veces construíamos esta cadena a mano solicitando URLs de la forma [http://localhost/appli? param1=val1&param2=val2&...]. En realidad, la información que el cliente envía al servidor procede de formularios que el usuario ha rellenado. En este capítulo exploramos cómo construir estos formularios. También presentamos la herramienta WebMatrix, que nos permitirá diseñar interfaces de usuario. La instalación de esta herramienta se describe en los apéndices.

    5.2.2.1. En

    form
    <formulario name="formulario" method="post">
    HTML tag
    <form name="..." method="..." action="...">...</form>
    attributes
    name="formexample": form name
    method="..." : method used by the browser to send the values collected in the form to the web server
    action="..." : URL to which the values collected in the form will be sent.
    Un formulario web está encerrado dentro de <form>...</form> etiquetas. El formulario puede tener un nombre (name="xx"). Se aplica a todos los controles de un formulario. Este nombre es útil si el documento web contiene scripts que necesitan hacer referencia a elementos del formulario. El propósito de un formulario es recoger la información introducida por el usuario a través del teclado o el ratón y enviarla a un servidor web URL. ¿Cuál? El referenciado en el action="URL" . Si falta este atributo, la información se enviará al URL del documento en el que se encuentra el formulario. ¿Cómo envía un cliente web la información (los datos contenidos en el formulario) a un servidor web? Ya lo hemos explicado en detalle. Puede utilizar dos métodos diferentes llamados POST y GET. El método="método" del atributo <form> donde method está definido como GET o POST, indica al navegador qué método debe utilizar para enviar la información recogida en el formulario al URL especificado por la etiqueta action="URL" atributo. Cuando el método no se especifica, se utiliza por defecto el método GET.

    5.2.2.2. Campo de entrada

    input field
    <entrada type="text" maxlength="30" value="algunas palabras" name="txtInput" />
    <entrada type="contraseña" maxlength="12" size="12" value="aPassword" name="txtMdp" />
    HTML tag
    <input type="..." name="..." size=".." value="..">
    La etiqueta de entrada existe para varios controles. Es la etiqueta tipo que distingue estos diferentes controles entre sí.
    attributes
    type="text": specifies that this is a text input field
    type="password": the characters in the input field are replaced by asterisks (*). This is the only difference from a normal input field. This type of control is suitable for entering passwords.
    size="12": number of characters visible in the field—does not prevent the entry of more characters
    maxlength="30": sets the maximum number of characters to 30—the browser is responsible for enforcing this attribute
    name="txtInput": name of the control
    value="some words": text that will be displayed in the input field.

    Sub Application_BeginRequest(ByVal sender As Object, ByVal e As EventArgs)
        ' retrieve the action to be performed
        Dim action As String
        If Request.QueryString("action") Is Nothing Then
            action = "init"
        Else
            action = Request.QueryString("action").ToString.ToLower
        End If
        ' execute the action
        Select Case action
            Case "init"

            Case "validation"
                Server.Transfer("validation.aspx", True)
            Case Else
                Server.Transfer("form.aspx", True)
        End Select

    • El usuario introduce y envía los datos. Se solicita el URL [http://localhost/mvcform2/?action=validation] y se recibe una respuesta. Se abre una nueva conexión TCP/IP y luego se cierra entre las dos partes.
    • El usuario hace clic en el enlace [Volver al formulario]. Se solicita el URL [http://localhost/mvcform2/?action=formulaire] y se recibe una respuesta. Se ha abierto una nueva conexión TCP/IP y luego se ha cerrado entre las dos partes.

    Los ciclos de solicitud-respuesta son independientes entre sí porque cada uno utiliza una nueva conexión TCP-IP. Cuando una aplicación cliente-servidor utiliza una única conexión TCP-IP para una serie de intercambios, el servidor puede identificar a un cliente a través de su conexión. Por lo tanto, puede almacenar información que vinculará a una conexión específica y así realizar un seguimiento de los intercambios. Cuando los intercambios se producen a través de conexiones diferentes, el servidor no puede identificar a un cliente por una conexión. Se necesita otro método. En el capítulo anterior presentamos uno de estos métodos: el mecanismo de sesión. Permite a los ciclos de solicitud-respuesta almacenar información en un objeto [Session] accesible a todos los ciclos posteriores.

    Ahora que tenemos una aplicación MVC con sesiones, ya no podemos utilizar el archivo [global.asax] como controlador, como se muestra en el capítulo anterior. El papel de controlador de la aplicación debe ser manejado por una página específica dedicada a este propósito. En este caso, será la página [main.aspx]. Procederemos como sigue:

    • Cuando el usuario envía sus datos (action=validation), el controlador [main.aspx.vb] los almacenará en la sesión actual antes de mostrar la página de validación.
    • Cuando sea necesario mostrar el formulario con los valores introducidos (action=form), el controlador [main.aspx.vb] los recuperará de la sesión y los colocará en el contexto antes de mostrar el formulario.

    Private Function getOptions(ByRef values() As String, ByRef labels() As String, ByRef selections() As String) As String
        ' returns the HTML code for the options of a <select> tag
        ' values: array of the tag's option values
        ' labels: array of the tag's option labels
        ' selections: options to be selected
        Dim iValue As Integer
        Dim iSelection As Integer
        Dim selected As String
        Dim toString As String = ""
        ' loop through the list of option values
        For iValue = 0 To values.Length - 1
            ' check if the current value should be selected
            selected = "" : iSelection = 0
            Do While iSelection < selections.Length And selected = ""
                If values(iValue) = selections(iSelection) Then selected = "selected"
                iSelection += 1
            Loop
            ' insert the HTML code for the option
            toString += "<option " + selected + " value='" + values(iValue) + "'> " _
            + labels(iValue) + "</option>" + ControlChars.CrLf
        Next
        ' we return the result
        Return toString
    End Function

    Tenga en cuenta que las opciones de una etiqueta <select> corresponden al siguiente código HTML:

    <option [selected] value="...">text</option>

    For each option, there are therefore three pieces of information to generate:

    • el valor de la opción en el atributo [value]
    • el texto de la opción entre las etiquetas <option> y </option>
    • la palabra clave [selected] si la opción debe seleccionarse en la lista

    Para generar estas tres informaciones para cada opción, la función [getOptions] recibe tres valores:

    1. la matriz de valores de opción en [valores]
    2. la matriz de textos de opciones en [labels]
    3. la matriz de valores a seleccionar en [selecciones]

    Private Function getValue(ByVal field As String) As String
        ' retrieves the value of the [field] field from the posted request

        If Request.Form(field) Is Nothing Then Return ""
