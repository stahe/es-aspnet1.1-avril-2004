    9.2.1. El ejemplo

    Considere la siguiente página:

    La página incluye tres componentes asociados a una lista de datos:

    • un componente [DataList] llamado [DataList1]
    • un componente [DataGrid] llamado [DataGrid1]

    9.2.2. Configuración de los componentes

    El componente [DataList1] se configura de la siguiente manera:

                            <FooterStyle ...></FooterStyle>
                            <HeaderStyle ...></HeaderStyle>
                        </asp:datalist>

    Hemos omitido todo lo relacionado con la apariencia del [DataList] para centrarnos únicamente en su contenido:

    • la sección <HeaderTemplate> define la cabecera del [DataList], y la sección <FooterTemplate> define su pie.
    • La sección <ItemTemplate> es la plantilla de visualización utilizada para cada elemento de la lista de datos asociada. Contiene los siguientes elementos:
      • el valor del dato actual de la lista de datos asociada al componente: <%# Container.DataItem %>
      • dos botones denominados [Info1] e [Info2], respectivamente. La clase [Button] tiene un atributo [CommandName] que se utiliza aquí. Nos permitirá determinar qué botón desencadenó un evento en el [DataList]. Para manejar los clics de los botones, tendremos un único manejador de eventos vinculado al propio [DataList], no a los botones. Este manejador recibirá información indicando en qué fila del [DataList] se ha producido el clic. El atributo [CommandName] nos permitirá saber qué botón de esa fila provocó el clic.

    El componente [Repetidor1] se configura de forma muy similar:

                                [start]<hr />

                            </ItemTemplate>
                        </asp:repeater>

    Simplemente añadimos una sección <SeparatorTemplate> para que los sucesivos datos que muestre el componente estén separados por una barra horizontal.

                              </asp:ButtonColumn>

                              </asp:ButtonColumn>

    Aquí también hemos omitido la información de estilo (colores, anchos, etc.). Estamos en modo de generación automática de columnas, que es el modo por defecto para el [DataGrid]. Esto significa que habrá tantas columnas como haya en la fuente de datos. Aquí hay una. Hemos añadido otras dos columnas marcadas con <asp:ButtonColumn>. Definimos información similar a la definida para las otras dos componentes, así como el tipo de botón, que aquí es [PushButton]. El tipo por defecto para es [LinkButton], i.e., un enlace. Además, los datos se paginarán [AllowPaging=true] con un tamaño de página de dos elementos [PageSize=2].

    El código de control de la aplicación se ha colocado en el [main.aspx.vbarchivo:

    Public Class main
    Inherits System.Web.UI.Page

    ' page components
    Protected WithEvents DataList1 As System.Web.UI.WebControls.DataList
    Protected WithEvents lblInfo As System.Web.UI.WebControls.Label
    Protected WithEvents DataGrid1 As System.Web.UI.WebControls.DataGrid
    Protected WithEvents Repeater1 As System.Web.UI.WebControls.Repeater

    ' the data source
    Protected texts() As String = {"zero", "one", "two", "three"}

    Private Sub Page_Load(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
        If Not IsPostBack Then
            'bind to data source
            DataList1.DataSource = texts
            DataGrid1.DataSource = texts
            Repeater1.DataSource = texts
            Page.DataBind()
        End If
    End Sub

    Private Sub DataList1_ItemCommand(ByVal source As Object, ByVal e As System.Web.UI.WebControls.DataListCommandEventArgs) Handles DataList1.ItemCommand
        ' An event occurred on one of the rows of the [datalist]
        lblInfo.Text = "You clicked the [" + e.CommandName + "] button on item [" + e.Item.ItemIndex.ToString + "] of the [DataList] component"
    End Sub

    Private Sub Repeater1_ItemCommand(ByVal source As Object, ByVal e As System.Web.UI.WebControls.RepeaterCommandEventArgs) Handles Repeater1.ItemCommand
        ' An event occurred on one of the rows of the [repeater]
        lblInfo.Text = "You clicked the [" + e.CommandName + "] button on the [" + e.Item.ItemIndex.ToString + "] item of the [Repeater] component"
    End Sub

    Private Sub DataGrid1_ItemCommand(ByVal source As Object, ByVal e As System.Web.UI.WebControls.DataGridCommandEventArgs) Handles DataGrid1.ItemCommand
        ' An event occurred on one of the rows of the [DataGrid]
        lblInfo.Text = "You clicked the [" + e.CommandName + "] button on the [" + e.Item.ItemIndex.ToString + "] item on page [" + DataGrid1.CurrentPageIndex.ToString() + "] of the [DataGrid] component"
    End Sub

    Private Sub DataGrid1_PageIndexChanged(ByVal source As Object, ByVal e As System.Web.UI.WebControls.DataGridPageChangedEventArgs) Handles DataGrid1.PageIndexChanged
        ' page change
        With DataGrid1
            .CurrentPageIndex = e.NewPageIndex
            .DataSource = texts
            .DataBind()
        End With
    End Sub

    Observaciones:

    • La fuente de datos [textes] es una simple matriz de cadenas. Se vinculará a los tres componentes de la página
    • Esta vinculación se establece en el procedimiento [Page_Load] durante la primera solicitud. Para las solicitudes posteriores, los tres componentes recuperarán sus valores mediante el mecanismo [VIEW_STATE].
    • Los tres componentes tienen un manejador para el evento [ItemCommand]. Este evento se produce cuando se hace clic en un botón o enlace de una de las filas del componente. El manejador recibe dos piezas de información:
      • fuente: la referencia al objeto (botón o enlace) que desencadenó el evento
      • a: información sobre el evento de tipo [DataListCommandEventArgs], [RepeaterCommandEventArgs], o [DataGridCommandEventArgs], según corresponda. El argumento a contiene varios datos. Aquí nos interesan dos de ellas:
        • a.Item: representa la fila en la que se ha producido el evento, de tipo [DataListItem], [DataGridItem] o [RepeaterItem]. Independientemente del tipo exacto, el elemento [Item] tiene un valor [ItemIndexque indica el número de fila del [Elemento] en el contenedor al que pertenece. Aquí, mostramos este número de fila
        • a.CommandName: es el atributo [CommandName] del botón (Button, LinkButton, ImageButton) que desencadenó el evento. Esta información, combinada con la anterior, nos permite determinar qué botón del contenedor desencadenó el evento [ItemCommand]

    9.3.5. Controladores

    La lógica de control se distribuye entre los ficheros [global.asax] y [main.aspx]. El archivo [global.asax] es el siguiente:

    <%@ Application src="global.asax.vb" inherits="global" %>

    El [global.asax.vbcontiene el siguiente código:

    
Imports System.Web
Imports System.Web.SessionState
Imports System.Data
Imports System
 
Public Class global
    Inherits System.Web.HttpApplication
 
    Sub Application_Start(ByVal sender As Object, ByVal e As EventArgs)
        ' Initialize the data source
        Dim themes As New DataTable
        ' columns
        With themes.Columns
            .Add("id", GetType(System.Int32))
            .Add("theme", GetType(System.String))
            .Add("description", GetType(System.String))
        End With
        ' The 'id' column will be the primary key
        themes.Constraints.Add("primary_key", themes.Columns("id"), True)
        ' rows
        Dim row As DataRow
        For i As Integer = 0 To 10
            row = themes.NewRow
            row.Item("id") = i.ToString
            row.Item("theme") = "theme" + i.ToString
            row.Item("description") = "theme description " + i.ToString
            themes.Rows.Add(row)
        Next
        ' Set the data source in the application
        Application("themes") = themes
    End Sub
 
    Sub Session_Start(ByVal sender As Object, ByVal e As EventArgs)
        ' Start of session - create an empty subscriptions table
        Dim dtSubscriptions As New DataTable
        With dtSubscriptions
            ' the columns
            .Columns.Add("id", GetType(String))
            .Columns.Add("theme", GetType(String))
            ' the primary key
            .PrimaryKey = New DataColumn() {.Columns("id")}
        End With
        ' the table is added to the session
        Session.Item("subscriptions") = dtSubscriptions
    End Sub
 
End Class

    El procedimiento [Application_Start], ejecutado cuando la aplicación recibe su primera petición, construye el [DataTable] de temas a los que se puede suscribir. Se construye arbitrariamente mediante código. Recordemos la técnica que ya hemos visto. Construimos en el siguiente orden:

    • un objeto [DataTable] vacío, sin estructura ni datos
    • la estructura de la tabla definiendo sus columnas (nombre y tipo de datos)
    • las filas de la tabla que representan los datos útiles

    Aquí hemos añadido una clave primaria. La columna "id" sirve como clave primaria. Hay varias formas de expresar esto. En este caso, hemos utilizado una restricción. En SQL, una restricción es una regla que los datos de una fila deben seguir para que esa fila se añada a una tabla. Hay todo tipo de restricciones posibles. La restricción de "clave primaria" obliga a que la columna a la que se aplica tenga valores únicos y no vacíos. En realidad, una clave primaria puede consistir en una expresión que incluya valores de varias columnas. [DataTable].Constraints es la colección de restricciones para una tabla determinada. Para añadir una restricción, se utiliza el método [DataTable.Constraints.Add]. Este método tiene varias firmas.     nombre de la restricción - puede ser cualquier cosa
    column
    columna que será la clave primaria - de tipo [DataColumn]
    primaryKey
    debe establecerse en [true] para que [columna] sea una clave primaria. Si [primaryKey=false], sólo se aplica la restricción única a [columna]

    Para hacer que la columna llamada "id" sea la clave primaria de la tabla [dtAbonnements], escribimos:

    Private Sub changePAC()
        ' makes the pAC page the current page for the
        ' manages the pages of the [datalist]
        Dim nbSubscriptions = dtSubscriptions.Rows.Count
        Dim lastPage = (nbSubscriptions - 1) \ nbAP

        If pAC < 0 Then pAC = 0
        If pAC > lastPage Then pAC = lastPage
        Dim first As Integer = pAC * nbAP
        Dim last As Integer = (pAC + 1) * nbAP - 1
        If last > numSubscriptions - 1 Then last = numSubscriptions - 1

        ' search for the [Previous] and [Next] links
        ' in the [DataList] control tree
        'Have we found all the links?
        If nbLinksFound = 2 Then Exit Sub
        ' Check child controls
        Dim c As Control
        For Each c In ctl.Controls
            ' First, we work in depth—the links are at the bottom of the tree
            setLinks(c, blPrevious, blNext, nbLinksFound)
            ' [Previous] link?
            If c.ID = "lnkPrecedent" Then
                CType(c, LinkButton).Visible = blPrec
                nbLinksFound += 1
            End If
            ' [Next] link?
            If c.ID = "lnkNext" Then
                CType(c, LinkButton).Visible = blNext
                nbLinksFound += 1
            End If
        Next
    End Sub

    El procedimiento es recursivo. Inicia la búsqueda desde la parte inferior del árbol de control porque es donde se encuentran. En cuanto se encuentra un enlace, el contador [nbLiensTrouvés] se incrementa, y la propiedad [visible] del enlace se establece al valor pasado como parámetro al procedimiento. Una vez encontrados ambos enlaces, el árbol de control deja de recorrerse y el procedimiento recursivo finaliza.

        Public Sub addProduct(ByVal product As sProduct)
            ' Add a product [name, price]
            ' prepare the parameters for the addition
            With insertCommand.Parameters
                .Clear()
                .Add(New OleDbParameter("name", product.name))
                .Add(New OleDbParameter("name", product.name))
            End With
            ' we make the addition
            Try
                ' open connection
                connection.Open()
                ' execute command
                insertCommand.ExecuteNonQuery()
            Catch ex As Exception
                ' problem
                Dim commandErrors As New ArrayList
                commandErrors.Add(String.Format("Error adding: {0}", ex.Message))
                Throw New ProductException(commandErrors)
            Finally
                ' Close connection
                connexion.Close()
            End Try

    El texto del comando [insert] SQL contiene parámetros formales que deben sustituirse por parámetros reales. Para ello se utiliza la colección [Parámetros] de la clase [OleDbCommand]. Esta colección contiene elementos de tipo [OleDbParameter] que definen los parámetros reales que deben sustituir a los parámetros formales ? Como no tienen nombre, el índice de los parámetros reales se utiliza para determinar qué parámetro formal corresponde a un parámetro real dado. En este caso, el parámetro real #i de la colección [Parameters] sustituirá al parámetro formal ? #i. El nombre puede ser cualquier cosa. Además, no se utilizará aquí. Los dos parámetros de la sentencia SQL [insertar] reciben como valores los de los campos [nombre, precio] de la estructura [producto]. Una vez hecho esto, la inserción la realiza la sentencia [insertCommand.ExecuteNonQuery].

        Dim defaultProductsPage As String = ConfigurationSettings.AppSettings("defaultProductsPage")

    • En primer lugar, comprobamos si la tabla de productos estaba cargada cuando se inició la aplicación. Si no es así, mostramos la vista [errores] con los mensajes de error apropiados y, a continuación, salimos del procedimiento tras establecer el booleano [error] en true. Este indicador será comprobado por ciertos procedimientos.
    • Recuperamos la tabla de productos [dtProduits] de la aplicación y la almacenamos en la variable de instancia [dtProduits] para que pueda ser compartida por todos los métodos de la página.
    • Hacemos lo mismo con la vista [dvProducts] recuperada de la sesión y el número predeterminado de productos por página recuperado de la aplicación.
    • If this is the client’s first request, we display the form for defining filtering and pagination conditions with a default pagination of [defaultProduitsPage] products per page.
    • Se cancela el modo de edición del componente [dataGrid1]. Este componente tiene un atributo [EditItemIndex], que es el índice del elemento que se está editando actualmente. Si [EditItemIndex]=-1, no se está editando ningún elemento. Si [EditItemIndex]=i, se está editando el elemento número i del componente [DataGrid]. Se mostrará de forma diferente a los demás elementos del componente [dataGrid]:

    Arriba, el elemento [Producto8, 80] está en modo [editar]. Como se muestra arriba, el usuario puede confirmar la actualización utilizando el enlace [Actualizar] o cancelarla utilizando el enlace [Cancelar]. También puede utilizar otros enlaces que no tienen nada que ver con el elemento que se está editando en ese momento. Al establecer [DataGrid1.EditItemIndex=-1] cada vez que se carga la página, nos aseguramos de que el modo de edición de [DataGrid1] se cancela sistemáticamente. Sólo le asignaremos un valor diferente si se ha hecho clic en un enlace [Editar]. Esto lo haremos en el procedimiento que gestiona este evento. Tendremos las siguientes situaciones:

    1. Se ha hecho clic en el enlace [Editar] del elemento #8 de [DataGrid1]. [Page_Load] primero establece [DataGrid1.EditItemIndex] en -1. Luego, el procedimiento que maneja el evento [Edit] establecerá [DataGrid1.EditItemIndex] a 8. Finalmente, cuando la página es enviada de vuelta al cliente, el ítem #8 estará efectivamente en modo [editar] y aparecerá como se muestra arriba.
    2. El usuario edita el producto que está en modo [editar] y confirma el cambio mediante el enlace [Actualizar]. [Page_Load] establece [DataGrid1.EditItemIndex] en -1. A continuación, se ejecutará el procedimiento que gestiona el evento [Actualizar] y se actualizará el elemento nº 8 de [dtProduits]. Cuando la página es enviada de vuelta al cliente, ningún elemento en [DataGrid1] estará en modo edición (DataGrid.EditItemIndex=-1).
    3. If a user has started updating a product, it would make sense for them to cancel this update by clicking [Cancel]. However, nothing prevents them from clicking another link. We must therefore account for this scenario. In this case, as in the previous ones, [Page_Load] begins by setting [DataGrid1.EditItemIndex] to -1, then the procedure handling the event that occurred will execute. It will not modify the [DataGrid1.EditItemIndex] property, which will therefore remain at -1. When the page is sent back to the client, no item in [DataGrid1] will be in edit mode.

    Podemos ver que estableciendo [EditItemIndex] a -1 cuando se carga la página, evitamos tener que preocuparnos de si el usuario estaba o no en modo edición cuando pulsó un enlace.

    El mecanismo funciona del siguiente modo:

    1. Uno o más clientes llegan a la declaración [Application.Lock] en la sección crítica 1. Este es un dispensador de fichas de una sola entrada. Un solo cliente obtiene este token. Llamémoslo C1.

    Private Sub deleteProduct(ByVal productId As Integer)
        Dim error As String
        Try
            ' synchronization
            Application.Lock()
            ' search for the row to delete
            Dim row As DataRow = dtProducts.Rows.Find(productId)
            If row Is Nothing Then
                error = String.Format("Product [{0}] does not exist", productId)
            Else
                ' Delete the row
                row.Delete()
            End If
        Catch ex As Exception
            error = String.Format("Delete error: {0}", ex.Message)
        Finally
            ' end of synchronization
            Application.UnLock()
        End Try
        ' throw an exception if an error occurs
        If error <> String.Empty Then Throw New Exception(error)
    End Sub

    9.7. Aplicación web para actualizar la tabla de productos físicos

    9.7.1. Soluciones propuestas

    La aplicación anterior era más un ejemplo de libro de texto destinado a demostrar la gestión de un objeto [DataTable] almacenado en caché que un escenario del mundo real. De hecho, en algún momento, la fuente de datos real debe ser actualizada. Se pueden elegir dos estrategias diferentes:

    1. Utilizamos la caché [dtProduits] en memoria para actualizar la fuente de datos. Se puede crear una página dentro del árbol web de la aplicación anterior para proporcionar acceso a su caché [dtProduits]. Esta página permitiría a un administrador sincronizar los cambios realizados en la caché [dtProduits] con la fuente de datos física. Para ello, podríamos añadir un nuevo método a la clase de acceso [products] que toma la caché [dtProduits] como parámetro y utiliza esta caché para actualizar la fuente de datos física.
    2. La fuente de datos física se actualiza al mismo tiempo que la caché.

    La estrategia nº 1 sólo permite abrir una conexión con la fuente de datos física. La estrategia nº 2 requiere una conexión para cada actualización. Dependiendo de la disponibilidad de la conexión, una estrategia puede ser preferible a la otra. Dado que disponemos de las herramientas para implementarla (la clase [products]), elegimos la estrategia #2.

    9.7.2. Solución 1

    For the sake of continuity with the previous application, we choose the following strategy:

    • la fuente física se actualiza al mismo tiempo que la caché
    • la caché se construye sólo una vez durante la inicialización de la aplicación en [global.asax.vb]. Esto significa que si la fuente de datos física es actualizada por clientes que no son clientes web, los clientes web no ven estos cambios. Sólo ven los cambios que ellos mismos realizan en la tabla almacenada en caché.

    9.8. Conclusión

    En este capítulo, hemos dedicado mucho tiempo a los contenedores de datos y sus conexiones con las fuentes de datos. Concluimos mostrando cómo actualizar una fuente de datos utilizando un componente [DataGrid]. Hemos utilizado una tabla de base de datos como fuente de datos. Aunque el componente [DataGrid] facilita un poco la presentación de los datos, el verdadero reto no reside en la capa de presentación, sino en la gestión de las actualizaciones de la fuente de datos realizadas por distintos clientes. Pueden surgir conflictos de acceso y hay que gestionarlos. Aquí, los gestionamos en el controlador utilizando [Application.Lock]. Probablemente sería más inteligente sincronizar el acceso a la fuente de datos dentro de la clase de acceso a datos para que el controlador no tenga que preocuparse de esos detalles que están fuera de su alcance.

    En la práctica, las tablas de una base de datos están vinculadas entre sí mediante relaciones, y sus actualizaciones deben tenerlas en cuenta. Esto afecta sobre todo a la clase de acceso a los datos, que se vuelve más compleja de lo necesario para una tabla independiente. También suele afectar a la capa de presentación de la aplicación web, ya que a menudo es necesario mostrar no una única tabla, sino tablas vinculadas entre sí a través de relaciones.

    Este capítulo también ha introducido varias estructuras de datos como [DataTable, DataView].
