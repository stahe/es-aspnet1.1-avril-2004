    9.1. Introducción

    9.2. Gestión de eventos asociados a datos en componentes vinculados a datos

    9.2.1. El ejemplo

    Considere la siguiente página:

    La página incluye tres componentes asociados a una lista de datos:

    • un componente [DataList] llamado [DataList1]
    • un componente [DataGrid] llamado [DataGrid1]
    • un componente [Repetidor] llamado [Repetidor1]

    La lista de datos asociada es la matriz {"cero", "uno", "dos", "tres"}. Cada uno de estos puntos de datos está asociado a un grupo de dos botones etiquetados como [Info1] e [Info2]. Cuando el usuario hace clic en uno de los botones, aparece un texto con el nombre del botón pulsado. El objetivo aquí es demostrar cómo gestionar una lista de botones o enlaces.

    9.2.2. Configuración de los componentes

    El componente [DataList1] se configura de la siguiente manera:

    
                        <asp:datalist id="DataList1" ... runat="server">
                            <SelectedItemStyle ...</SelectedItemStyle>
                            <HeaderTemplate>
                                [début]
                            </HeaderTemplate>
                            <FooterTemplate>
                                [fin]
                            </FooterTemplate>
                            <ItemStyle ...></ItemStyle>
                            <ItemTemplate>
                                <P><%# Container.DataItem %>
                                    <asp:Button runat="server" Text="Infos1" CommandName="infos1"></asp:Button>
                                    <asp:Button runat="server" Text="Infos2" CommandName="infos2"></asp:Button></P>
                            </ItemTemplate>
                            <FooterStyle ...></FooterStyle>
                            <HeaderStyle ...></HeaderStyle>
                        </asp:datalist>

    Hemos omitido todo lo relacionado con la apariencia del [DataList] para centrarnos únicamente en su contenido:

    • la sección <HeaderTemplate> define la cabecera del [DataList], y la sección <FooterTemplate> define su pie.
    • La sección <ItemTemplate> es la plantilla de visualización utilizada para cada elemento de la lista de datos asociada. Contiene los siguientes elementos:
      • el valor del dato actual de la lista de datos asociada al componente: <%# Container.DataItem %>
      • dos botones denominados [Info1] e [Info2], respectivamente. La clase [Button] tiene un atributo [CommandName] que se utiliza aquí. Nos permitirá determinar qué botón desencadenó un evento en el [DataList]. Para manejar los clics de los botones, tendremos un único manejador de eventos vinculado al propio [DataList], no a los botones. Este manejador recibirá información indicando en qué fila del [DataList] se ha producido el clic. El atributo [CommandName] nos permitirá saber qué botón de esa fila provocó el clic.

    El componente [Repetidor1] se configura de forma muy similar:

    
                        <asp:repeater id="Repeater1" runat="server">
                            <HeaderTemplate>
                                [début]<hr />
                            </HeaderTemplate>
                            <FooterTemplate>
                                <hr />
                                [fin]
                            </FooterTemplate>
                            <SeparatorTemplate>
                                <hr />
                            </SeparatorTemplate>
                            <ItemTemplate>
                                <%# Container.DataItem %>
                                <asp:Button runat="server" Text="Infos1" CommandName="infos1"></asp:Button>
                                <asp:Button runat="server" Text="Infos2" CommandName="infos2"></asp:Button></P>
                            </ItemTemplate>
                        </asp:repeater>

    Simplemente añadimos una sección <SeparatorTemplate> para que los sucesivos datos que muestre el componente estén separados por una barra horizontal.

    Por último, el componente [DataGrid1] se configura del siguiente modo:

    
                        <asp:datagrid id="DataGrid1" ... runat="server" PageSize="2" AllowPaging="True">
                            <SelectedItemStyle ...></SelectedItemStyle>
                            <AlternatingItemStyle ...></AlternatingItemStyle>
                            <ItemStyle ...></ItemStyle>
                            <HeaderStyle ...></HeaderStyle>
                            <FooterStyle ....></FooterStyle>
                            <Columns>
                                <asp:ButtonColumn Text="Infos1" ButtonType="PushButton" CommandName="Infos1">
                              </asp:ButtonColumn>
                                <asp:ButtonColumn Text="Infos2" ButtonType="PushButton" CommandName="Infos2">
                              </asp:ButtonColumn>
                            </Columns>
                            <PagerStyle .... Mode="NumericPages"></PagerStyle>
                        </asp:datagrid>

    Aquí también hemos omitido la información de estilo (colores, anchos, etc.). Estamos en modo de generación automática de columnas, que es el modo por defecto para el [DataGrid]. Esto significa que habrá tantas columnas como haya en la fuente de datos. Aquí hay una. Hemos añadido otras dos columnas marcadas con <asp:ButtonColumn>. Definimos información similar a la definida para las otras dos componentes, así como el tipo de botón, que aquí es [PushButton]. El tipo por defecto para es [LinkButton], i.e., un enlace. Además, los datos se paginarán [AllowPaging=true] con un tamaño de página de dos elementos [PageSize=2].

    El código de control de la aplicación se ha colocado en el [main.aspx.vbarchivo:

    Public Class main
    Inherits System.Web.UI.Page

    ' components page
    Protected WithEvents DataList1 As System.Web.UI.WebControls.DataList
    Protected WithEvents lblInfo As System.Web.UI.WebControls.Label
    Protected WithEvents DataGrid1 As System.Web.UI.WebControls.DataGrid
    Protected WithEvents Repeater1 As System.Web.UI.WebControls.Repeater

    ' the data source
    Protected textes() As String = {"zéro", "un", "deux", "trois"}

    Private Sub Page_Load(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
        If Not IsPostBack Then
            'data source links
            DataList1.DataSource = textes
            DataGrid1.DataSource = textes
            Repeater1.DataSource = textes
            Page.DataBind()
        End If
    End Sub

    Private Sub DataList1_ItemCommand(ByVal source As Object, ByVal e As System.Web.UI.WebControls.DataListCommandEventArgs) Handles DataList1.ItemCommand
        ' an event has occurred on one of the [datalist] lines
        lblInfo.Text = "Vous avez cliqué sur le bouton [" + e.CommandName + "] de l'élément [" + e.Item.ItemIndex.ToString + "] du composant [DataList]"
    End Sub

    Private Sub Repeater1_ItemCommand(ByVal source As Object, ByVal e As System.Web.UI.WebControls.RepeaterCommandEventArgs) Handles Repeater1.ItemCommand
        ' an event has occurred on one of the [repeater] lines
        lblInfo.Text = "Vous avez cliqué sur le bouton [" + e.CommandName + "] de l'élément [" + e.Item.ItemIndex.ToString + "] du composant [Repeater]"
    End Sub

    Private Sub DataGrid1_ItemCommand(ByVal source As Object, ByVal e As System.Web.UI.WebControls.DataGridCommandEventArgs) Handles DataGrid1.ItemCommand
        ' an event has occurred on one of the [datagrid] lines
        lblInfo.Text = "Vous avez cliqué sur le bouton [" + e.CommandName + "] de l'élément [" + e.Item.ItemIndex.ToString + "] de la page [" + DataGrid1.CurrentPageIndex.ToString() + "] du composant [DataGrid]"
    End Sub

    Private Sub DataGrid1_PageIndexChanged(ByVal source As Object, ByVal e As System.Web.UI.WebControls.DataGridPageChangedEventArgs) Handles DataGrid1.PageIndexChanged
        ' change page
        With DataGrid1
            .CurrentPageIndex = e.NewPageIndex
            .DataSource = textes
            .DataBind()
        End With

    Observaciones:

    • La fuente de datos [textes] es una simple matriz de cadenas. Se vinculará a los tres componentes de la página
    • Esta vinculación se establece en el procedimiento [Page_Load] durante la primera solicitud. Para las solicitudes posteriores, los tres componentes recuperarán sus valores mediante el mecanismo [VIEW_STATE].
    • Los tres componentes tienen un manejador para el evento [ItemCommand]. Este evento se produce cuando se hace clic en un botón o enlace de una de las filas del componente. El manejador recibe dos piezas de información:
      • fuente: la referencia al objeto (botón o enlace) que desencadenó el evento
      • a: información sobre el evento de tipo [DataListCommandEventArgs], [RepeaterCommandEventArgs], o [DataGridCommandEventArgs], según corresponda. El argumento a contiene varios datos. Aquí nos interesan dos de ellas:
        • a.Item: representa la fila en la que se ha producido el evento, de tipo [DataListItem], [DataGridItem] o [RepeaterItem]. Independientemente del tipo exacto, el elemento [Item] tiene un valor [ItemIndexque indica el número de fila del [Elemento] en el contenedor al que pertenece. Aquí, mostramos este número de fila
        • a.CommandName: es el atributo [CommandName] del botón (Button, LinkButton, ImageButton) que desencadenó el evento. Esta información, combinada con la anterior, nos permite determinar qué botón del contenedor desencadenó el evento [ItemCommand]

    9.3.5. Controladores

    La lógica de control se distribuye entre los ficheros [global.asax] y [main.aspx]. El archivo [global.asax] es el siguiente:

    <%@ Application src="global.asax.vb" inherits="global" %>

    El [global.asax.vbcontiene el siguiente código:

    
Imports System.Web
Imports System.Web.SessionState
Imports System.Data
Imports System
 
Public Class global
    Inherits System.Web.HttpApplication
 
    Sub Application_Start(ByVal sender As Object, ByVal e As EventArgs)
        ' initialize the data source
        Dim thèmes As New DataTable
        ' columns
        With thèmes.Columns
            .Add("id", GetType(System.Int32))
            .Add("thème", GetType(System.String))
            .Add("description", GetType(System.String))
        End With
        ' column id will be primary key
        thèmes.Constraints.Add("cléprimaire", thèmes.Columns("id"), True)
        ' lines
        Dim ligne As DataRow
        For i As Integer = 0 To 10
            ligne = thèmes.NewRow
            ligne.Item("id") = i.ToString
            ligne.Item("thème") = "thème" + i.ToString
            ligne.Item("description") = "description du thème " + i.ToString
            thèmes.Rows.Add(ligne)
        Next
        ' put the data source in the application
        Application("thèmes") = thèmes
    End Sub
 
    Sub Session_Start(ByVal sender As Object, ByVal e As EventArgs)
        ' start of session - create an empty subscriptions table
        Dim dtAbonnements As New DataTable
        With dtAbonnements
            ' the columns
            .Columns.Add("id", GetType(String))
            .Columns.Add("thème", GetType(String))
            ' the primary key
            .PrimaryKey = New DataColumn() {.Columns("id")}
        End With
        ' the table is placed in the session
        Session.Item("abonnements") = dtAbonnements
    End Sub
 
End Class

    El procedimiento [Application_Start], ejecutado cuando la aplicación recibe su primera petición, construye el [DataTable] de temas a los que se puede suscribir. Se construye arbitrariamente mediante código. Recordemos la técnica que ya hemos visto. Construimos en el siguiente orden:

    • un objeto [DataTable] vacío, sin estructura ni datos
    • la estructura de la tabla definiendo sus columnas (nombre y tipo de datos)
    • las filas de la tabla que representan los datos útiles

    Aquí hemos añadido una clave primaria. La columna "id" sirve como clave primaria. Hay varias formas de expresar esto. En este caso, hemos utilizado una restricción. En SQL, una restricción es una regla que los datos de una fila deben seguir para que esa fila se añada a una tabla. Hay todo tipo de restricciones posibles. La restricción de "clave primaria" obliga a que la columna a la que se aplica tenga valores únicos y no vacíos. En realidad, una clave primaria puede consistir en una expresión que incluya valores de varias columnas. [DataTable].Constraints es la colección de restricciones para una tabla determinada. Para añadir una restricción, se utiliza el método [DataTable.Constraints.Add]. Este método tiene varias firmas. Aquí, usamos el método [Add(Byval name as String, Byval column as DataColumn, Byval primaryKey as Boolean)]:

    name
    nombre de la restricción - puede ser cualquier cosa
    column
    columna que será la clave primaria - de tipo [DataColumn]
    primaryKey
    debe establecerse en [true] para que [columna] sea una clave primaria. Si [primaryKey=false], sólo se aplica la restricción única a [columna]

    Para hacer que la columna llamada "id" sea la clave primaria de la tabla [dtAbonnements], escribimos:

    dtAbonnements.Constraints.Add("xxx",dtAbonnements.Columns("id"),true)

        ' datalist] page management
        Dim nbAbonnements = dtAbonnements.Rows.Count
        Dim dernièrePage = (nbAbonnements - 1) \ nbAP

        If pAC < 0 Then pAC = 0
        If pAC > dernièrePage Then pAC = dernièrePage

        ' search for [previous] and [next] links
        ' in the [datalist] control tree
        ' have all the links been found?
        If nbLiensTrouvés = 2 Then Exit Sub
        ' review of child controls
        Dim c As Control
        For Each c In ctl.Controls
            ' we work deep down first - the links are at the bottom of the tree
            setLiens(c, blPrec, blSuivant, nbLiensTrouvés)
            ' link [Previous] ?
            If c.ID = "lnkPrecedent" Then
                CType(c, LinkButton).Visible = blPrec
                nbLiensTrouvés += 1
            End If
            ' next] link ?
            If c.ID = "lnkSuivant" Then
                CType(c, LinkButton).Visible = blSuivant
                nbLiensTrouvés += 1
            End If
        Next
    End Sub

Inicia la búsqueda desde la parte inferior del árbol de control porque es donde se encuentran. En cuanto se encuentra un enlace, el contador [nbLiensTrouvés] se incrementa, y la propiedad [visible] del enlace se establece al valor pasado como parámetro al procedimiento.             End Try
        End If

            ' errors are noted

    Private Sub supprimerProduit(ByVal idProduit As Integer)
        Dim erreur As String
        Try
            ' synchronization
            Application.Lock()
            ' search for the line to be deleted
            Dim ligne As DataRow = dtProduits.Rows.Find(idProduit)
            If ligne Is Nothing Then

            Else
                ' delete line
                ligne.Delete()
            End If
        Catch ex As Exception
            erreur = String.Format("Erreur de suppression : {0}", ex.Message)
        Finally
            ' end of synchronization
            Application.UnLock()
        End Try
        ' throw an exception if error
        If erreur <> String.Empty Then Throw New Exception(erreur)
    End Sub

    9.7. Aplicación web para actualizar la tabla de productos físicos

    9.7.1. Soluciones propuestas

    La aplicación anterior era más un ejemplo de libro de texto destinado a demostrar la gestión de un objeto [DataTable] almacenado en caché que un escenario del mundo real. De hecho, en algún momento, la fuente de datos real debe ser actualizada. Se pueden elegir dos estrategias diferentes:

    1. Utilizamos la caché [dtProduits] en memoria para actualizar la fuente de datos. Se puede crear una página dentro del árbol web de la aplicación anterior para proporcionar acceso a su caché [dtProduits]. Esta página permitiría a un administrador sincronizar los cambios realizados en la caché [dtProduits] con la fuente de datos física. Para ello, podríamos añadir un nuevo método a la clase de acceso [products] que toma la caché [dtProduits] como parámetro y utiliza esta caché para actualizar la fuente de datos física.
    2. La fuente de datos física se actualiza al mismo tiempo que la caché.

    La estrategia nº 1 sólo permite abrir una conexión con la fuente de datos física. La estrategia nº 2 requiere una conexión para cada actualización. Dependiendo de la disponibilidad de la conexión, una estrategia puede ser preferible a la otra. Dado que disponemos de las herramientas para implementarla (la clase [products]), elegimos la estrategia #2.

    9.7.2. Solución 1

    For the sake of continuity with the previous application, we choose the following strategy:

    • la fuente física se actualiza al mismo tiempo que la caché
    • la caché se construye sólo una vez durante la inicialización de la aplicación en [global.asax.vb]. Esto significa que si la fuente de datos física es actualizada por clientes que no son clientes web, los clientes web no ven estos cambios. Sólo ven los cambios que ellos mismos realizan en la tabla almacenada en caché.

    Protected nbProduitsPage As Integer

    Private Sub Page_Load(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
        ' check for application errors
        If Not IsNothing(Application("erreurs")) Then
            ' the application has not initialized correctly
            afficheErreurs(CType(Application("erreurs"), ArrayList))
            Exit Sub
        End If
        ' check for session errors
        If Not IsNothing(Session("erreurs")) Then
            ' the session has not initialized correctly
            afficheErreurs(CType(Session("erreurs"), ArrayList))
            Exit Sub
        End If
        ' retrieve a reference from the product table
        dtProduits = CType(Session("dtProduits"), DataTable)
        ' product view
        dvProduits = CType(Session("dvProduits"), DataView)
        ' retrieve the number of products per page
        nbProduitsPage = CType(Session("nbProduitsPage"), Integer)
        ' retrieve the current page
        pageCourante = CType(Session("pageCourante"), Integer)
        ' retrieve the product access instance
        objProduits = CType(Application("objProduits"), produits)
        ' cancels any update in progress
        DataGrid1.EditItemIndex = -1
        '1st request
        If Not IsPostBack Then
            ' the initial form is displayed
            txtPages.Text = nbProduitsPage.ToString
            afficheFormulaire()
        End If
    End Sub

    La información obtenida durante la sesión se guardará al final de la misma después de cada solicitud:

    
    Private Sub Page_PreRender(ByVal sender As Object, ByVal e As System.EventArgs) Handles MyBase.PreRender
        ' certain information is stored in the session
        Session("dtProduits") = dtProduits
        Session("dvProduits") = dvProduits
        Session("nbProduitsPage") = nbProduitsPage
        Session("pageCourante") = pageCourante
    End Sub

    El evento [PreRender] indica que la respuesta está a punto de ser enviada al cliente. Aprovechamos esta oportunidad para guardar todos los datos que deben conservarse en la sesión. Esto es excesivo, ya que a menudo sólo una parte de los datos ha cambiado. Este guardado sistemático tiene la ventaja de liberarnos de la gestión de la sesión en los otros métodos de la página.

    La operación de actualización de la caché se realiza mediante el siguiente procedimiento:

    
    Private Sub lnkRefresh_Click(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles lnkRefresh.Click
        ' refresh the [dtProduits] cache with the physical data source
        ' synchro start
        Application.Lock()
        Try
            ' product table
            dtProduits = CType(Application("objProduits"), produits).getProduits
            ' the current filter is saved
            Dim filtre As String = dvProduits.RowFilter
            ' create the new filtered view
            dvProduits = New DataView(dtProduits)
            ' put the filter back on
            dvProduits.RowFilter = filtre
        Catch ex As ExceptionProduits
            'there has been an error accessing the products, this is noted in the session
            Session("erreurs") = ex.erreurs
            ' display the [errors] view
            afficheErreurs(ex.erreurs)
            ' finish
            Exit Sub
        Finally
            ' end synchro
            Application.UnLock()
        End Try
        ' it went well - the products are displayed from the 1st page
        afficheProduits(0, nbProduitsPage)
    End Sub

    El procedimiento regenera nuevos valores para la caché [dtProduits] y la vista [dvProduits]. Éstos se colocarán en la sesión mediante el procedimiento [Page_PreRender] descrito anteriormente. Una vez reconstruida la caché [dtProduits], mostramos los productos empezando por la primera página.

    9.8. Conclusión

    En este capítulo, hemos dedicado mucho tiempo a los contenedores de datos y sus conexiones con las fuentes de datos. Concluimos mostrando cómo actualizar una fuente de datos utilizando un componente [DataGrid]. Hemos utilizado una tabla de base de datos como fuente de datos. Aunque el componente [DataGrid] facilita un poco la presentación de los datos, el verdadero reto no reside en la capa de presentación, sino en la gestión de las actualizaciones de la fuente de datos realizadas por distintos clientes. Pueden surgir conflictos de acceso y hay que gestionarlos. Aquí, los gestionamos en el controlador utilizando [Application.Lock]. Probablemente sería más inteligente sincronizar el acceso a la fuente de datos dentro de la clase de acceso a datos para que el controlador no tenga que preocuparse de esos detalles que están fuera de su alcance.

    En la práctica, las tablas de una base de datos están vinculadas entre sí mediante relaciones, y sus actualizaciones deben tenerlas en cuenta. Esto afecta sobre todo a la clase de acceso a los datos, que se vuelve más compleja de lo necesario para una tabla independiente. También suele afectar a la capa de presentación de la aplicación web, ya que a menudo es necesario mostrar no una única tabla, sino tablas vinculadas entre sí a través de relaciones.
