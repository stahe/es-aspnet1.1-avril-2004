    8.2.1. Introducción

    En las aplicaciones basadas en formularios, es esencial verificar la validez de los datos introducidos en ellos. En el ejemplo del cálculo de impuestos, teníamos el siguiente formulario:

    Al recibir los valores de este formulario, debemos verificar la validez de los datos introducidos: el número de hijos y el salario deben ser enteros positivos o cero. Si no es así, el formulario se devuelve al cliente tal y como se introdujo, junto con mensajes de error. Manejamos este escenario utilizando dos vistas, una para el formulario anterior y otra para los errores:

    ASP.NET ofrece componentes denominados componentes de validación que permiten comprobar lo siguiente:

    Componente
    Papel
    RequiredFieldValidator
    comprueba que un campo no esté vacío
    CompareValidator
    comprueba dos valores entre sí
    RangeValidator
    comprueba que un valor se encuentra entre dos límites
    RegularExpressionValidator
    comprueba si un campo coincide con una expresión regular

        e.isvalid = not (cmbDiplomes.selecteditem.text = "[Other]" and txtAutreDiplome.text.trim = "") _
            and not (cmbDiplomes.selecteditem.text <> "[Other]" and cmbDiplomes.selecteditem.text <> "?" and txtAutreDiplome.text.trim <> "")
    End Sub

</script>
....

    Una función de validación asociada a un componente [CustomValidator] recibe dos parámetros:

    • remitente: el objeto que desencadenó el evento
    • e: el evento. El procedimiento debe establecer la propiedad [e.IsValid] a true si los datos validados son correctos, y a false en caso contrario.

    Aquí se realizan las siguientes comprobaciones:

    • la lista desplegable [cmbDiplomes] no puede tener [?] como valor. Esto se verifica mediante el componente [CompareValidator2]
    • el usuario selecciona una titulación de la lista desplegable [cmbDiplomes]. Si su titulación no figura en la lista, puede seleccionar la opción [Otros] de la lista. A continuación, deberá introducir su titulación en el campo de entrada [txtAutreDiplome]. Si se selecciona [Otro] en [cmbDiplomes], el campo [txtAutreDiplome] no debe estar vacío.     • El año de obtención del título debe estar comprendido entre [1900-2004]. Esto se verifica mediante [RangeValidator1]. Sin embargo, si el usuario deja el campo en blanco, no se utiliza la función de validación de [RangeValidator1]. Por lo tanto, añadimos el componente [RequiredFieldValidator2] al [ ] para comprobar la presencia de contenido. Se trata de una regla general. El contenido de un campo no se comprueba si está vacío. Para ello utilizamos un componente [RegularExpressionValidator], que nos permite validar un campo utilizando una expresión regular. Recuerde que una expresión regular es un patrón de caracteres. Por lo tanto, comparamos el contenido de un campo con un patrón. La clase [RegularExpressionValidator] tiene propiedades similares a las de las clases componentes ya tratadas:

    EnableClientScript
    boolean - cuando es true, indica que el contenido del campo anterior también debe ser validado en el lado del cliente

    RegularExpression

Este campo también existe para otros componentes, pero no se había utilizado hasta ahora.

    El patrón de expresión regular para una dirección de correo electrónico podría ser el siguiente: \s*[\w-]+(\.[\w-]+)*@[\w-]+(\.[\w-]+)+\s*

    Una dirección de correo electrónico tiene la forma [champ1.champ2....@champA.champB...]. Debe haber al menos un campo antes del signo @ y al menos dos campos después. Estos campos están formados por caracteres alfanuméricos y el signo -. Un carácter alfanumérico se representa mediante el símbolo \w. La secuencia [\w-] significa el carácter \w o el carácter -. El signo + después de una secuencia S significa que puede repetirse 1 o más veces; el signo * significa que puede repetirse 0 o más veces; el signo ? significa que puede repetirse 0 o 1 vez.

    Un campo en la dirección de correo electrónico corresponde al patrón [\w-]+. El hecho de que deba haber al menos un campo antes del signo @ y al menos dos después, separados por el signo ., corresponde al patrón: [\w-]+(\.[\w-]+)*@[\w-]+(\.[\w-]+)+. Podemos permitir que el usuario incluya espacios antes y después de la dirección. Éstos se eliminarán durante el procesamiento. Una secuencia de espacios, que puede estar vacía, se representa mediante el patrón \s*. De ahí la expresión regular para la dirección de correo electrónico: \s*[\w-]+(\.[\w-]+)*@[\w-]+(\.[\w-]+)+\s*.

    8.3. ListControl Componentes y enlace de datos

    Algunos de los componentes de servidor tratados permiten mostrar una lista de valores (DropDownList, ListBox). Otros que aún no hemos tratado permiten mostrar varias listas de valores en tablas HTML. Para todos ellos, es posible asociar mediante programación los valores de las listas con el componente correspondiente uno a uno. También es posible asociar objetos más complejos a estos componentes, como objetos de tipo [Array], [ArrayList], [DataSet], [HashTable], etc., lo que simplifica el código que asocia los datos al componente. Esta asociación se denomina enlace de datos.

    Todos los componentes derivados de la clase [ListControl] pueden asociarse a una lista de datos. Entre ellos se incluyen los componentes [DropDownList], [ListBox], [CheckButtonList] y [RadioButtonList]. Cada uno de estos componentes puede vincularse a una fuente de datos. Ésta puede adoptar diversas formas: [Array], [ArrayList], [DataTable], [DataSet], [HashTable], ... generalmente un objeto que implemente una de las interfaces IEnumerable, ICollection, o IListSource. Aquí sólo presentaremos algunas de ellas. Un objeto [DataSet] es una representación de una base de datos relacional. Se trata, por tanto, de un conjunto de tablas vinculadas por relaciones. El objeto [DataTable] representa una tabla de este tipo. La fuente de datos establece las propiedades [Texto] y [Valor] de cada [Elemento] en el objeto [ListControl]. Si T es el valor de [Texto] y V es el valor de [Valor], la etiqueta HTML generada para cada elemento de [ListControl] es la siguiente:

    DropDownList, ListBox
    <opción value="V">T</opción>
    CheckButtonList
    <input type="checkbox" value="V">T
    RadioButtonList
    <input type="radio" value="V">T

    Un componente [ListControl] se asocia a una fuente de datos mediante las siguientes propiedades:

    DataSource
    una fuente de datos [Array], [ArrayList], [DataTable], [DataSet], [HashTable], ...
    DataMember
    if the data source is a [DataSet], represents the name of the table to be used as the data source. The actual data source is then a table.
    DataTextField
    if the data source is a table ([DataTable], [DataSet]), represents the name of the table column that will provide values to the [Text] field of the [ListControl] items
    DataValueField
    if the data source is a table ([DataTable], [DataSet]), represents the name of the table column that will provide values to the [Value] field of the [ListControl] elements

    La vinculación de un componente [ListControl] a una fuente de datos no inicializa el componente con los valores de la fuente de datos. La dirección [ListControl].DataBind operación hace esto.

    Dependiendo de la naturaleza de la fuente de datos, su vinculación a un componente [ListControl] se realizará de forma diferente:

    Array A
    [ListControl].DataSource=A
    Los campos [Texto] y [Valor] de los elementos [ListControl] tendrán los valores de los elementos de A
    ArrayList AL
    [ListControl].DataSource=AL
    Los campos [Texto] y [Valor] de los elementos [ListControl] tendrán los valores de los elementos de AL
    DataTable DT
    [ListControl].DataSource = DT, [ListControl].DataTextField = "col1", [ListControl].DataValueField = "col2"
    donde col1 y col2 son dos columnas de la tabla DT. Los campos [Texto] y [Valor] de los elementos [ListControl] tendrán los valores de las columnas col1 y col2 de la tabla DT
    DataSet DS
    [ListControl].DataSource=DS, [ListControl].DataSource="tabla" donde "tabla" es el nombre de una de las tablas en DS.
    [ListControl].DataTextField="col1", [ListControl].DatavalueField ="col2" donde col1 y col2 son dos columnas de la tabla "tabla". Los campos [Texto] y [Valor] de los elementos [ListControl] tendrán los valores de las columnas col1 y col2 de la tabla "tabla"
    HashTable HT
    [ListControl].DataSource = HT, [ListControl].DataTextField = "clave", [ListControl].DataValueField = "valor", donde [clave] y [valor] son las claves y los valores de HT, respectivamente.

    Private Sub Page_Load(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
        ' First, we check the state of the application
        If CType(Application("error"), Boolean) Then
            ' the application failed to initialize
            ' we display the errors view
            Dim errors As New ArrayList
            errors.Add("Application temporarily unavailable (" + CType(Application("message"), String) + ")")

        ' We check the validity of the entered data; if there are errors, we report them
        If Not Page.IsValid Then
            displayForm()
            Exit Sub
        End If
        ' No errors—calculate the tax
        Dim taxAsLong As Long = CType(Application("objImpot"), tax).Calculate( _
        rdYes.Checked, CType(txtChildren.Text, Integer), CType(txtSalary.Text, Long))
        ' Add the result to the existing simulations
        Dim simulations As DataTable = CType(Session.Item("simulations"), DataTable)
        Dim simulation As DataRow = simulations.NewRow
        simulation("married") = CType(IIf(rdYes.Checked, "yes", "no"), String)
        simulation("children") = txtChildren.Text.Trim
        simulation("salary") = CType(txtSalary.Text.Trim, Long)
