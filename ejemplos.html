    6.1. Ejemplo 1

    6.1.1. El problema

    Esta aplicación debe permitir al usuario calcular sus impuestos. Estamos considerando el caso simplificado de un contribuyente que sólo tiene que declarar su sueldo (cifras de 2004 para ingresos de 2003):

    • Calculamos el número de tramos impositivos para el asalariado as nbParts = nbEnfants / 2 + 1 si no están casados, y nbEnfants / 2 + 2 si están casados, dónde nbEnfants es el número de hijos.
    • If he has at least three children, he is entitled to an additional half-share
    • Su base imponible R se calcula como R = 0,72 * S, donde S es su salario anual
    • Calculamos su coeficiente familiar QF = R / nbParts

    6.1.2. La estructura MVC de la aplicación

    La estructura MVC de la aplicación será la siguiente:

    La función de controlador será gestionada por la página [main.aspx]. Habrá tres acciones posibles:

    • init: corresponde a la primera petición del cliente. El controlador mostrará la vista [formulaire.aspx]
    • calcular: corresponde a la solicitud de cálculo del impuesto. Si los datos del formulario de entrada son correctos, el impuesto se calcula utilizando la clase de negocio [impots]. El controlador devuelve al cliente la vista [form.aspx] tal y como fue validada, junto con el impuesto calculado. Si los datos del formulario de entrada son incorrectos, el controlador devolverá la vista [errors.aspx] con una lista de errores y un enlace para volver al formulario.
    • devolver: corresponde a volver al formulario después de un error. El controlador muestra la vista [form.aspx] tal y como estaba validada antes del error.

    El controlador [main.aspx] no sabe nada de cálculos fiscales. Simplemente es responsable de gestionar el diálogo cliente-servidor y ejecutar las acciones solicitadas por el cliente. Para la acción [calculate], se apoyará en la clase de negocio [tax].

    6.1.3. La clase business

    El **impot** se definirá de la siguiente manera:

    
' imported namespaces
Imports System
 
' class
Namespace st.istia.univangers.fr
    Public Class impot
        Private limites(), coeffR(), coeffN() As Decimal
 
        ' manufacturer
        Public Sub New(ByRef source As impotsData)
            ' data required for tax calculation
            ' come from an external source [source]
            ' we retrieve them - there may be an exception
            Dim data() As Object = source.getData
            limites = CType(data(0), Decimal())
            coeffR = CType(data(1), Decimal())
            coeffN = CType(data(2), Decimal())
        End Sub
 
        ' tAX CALCULATION
        Public Function calculer(ByVal marié As Boolean, ByVal nbEnfants As Integer, ByVal salaire As Long) As Long
            ' calculating the number of shares
            Dim nbParts As Decimal
            If marié Then
                nbParts = CDec(nbEnfants) / 2 + 2
            Else
                nbParts = CDec(nbEnfants) / 2 + 1
            End If
            If nbEnfants >= 3 Then
                nbParts += 0.5D
            End If
            ' calculation of taxable income & family quota
            Dim revenu As Decimal = 0.72D * salaire
            Dim QF As Decimal = revenu / nbParts
            ' tAX CALCULATION
            limites((limites.Length - 1)) = QF + 1
            Dim i As Integer = 0
            While QF > limites(i)
                i += 1
            End While
            Return CLng(revenu * coeffR(i) - nbParts * coeffN(i))
        End Function
    End Class
End Namespace

    A fiscal proporcionando a su constructor una fuente de datos de tipo [impotsData]. Esta clase tiene un método público [getDataque recupera las tres matrices de datos necesarias para calcular el impuesto, como se ha descrito anteriormente. Este método puede manejar una excepción si los datos no se han podido recuperar o si son incorrectos. Una vez creado el objeto [tax], su método calcular puede llamarse repetidamente para calcular los impuestos del contribuyente en función de su estado civil (casado o soltero), número de hijos y salario anual.

    6.1.4. La clase de acceso a los datos

    La clase [impotsData] es la clase que proporciona acceso a los datos. Es una clase abstracta. Debe crearse una clase derivada para cada nueva fuente de datos posible (matrices, ficheros planos, bases de datos, consola, etc.). Su definición es la siguiente:

    
Imports System.Collections
 
Namespace st.istia.univangers.fr
    Public MustInherit Class impotsData
        Protected limites() As Decimal
        Protected coeffr() As Decimal
        Protected coeffn() As Decimal
        Protected checked As Boolean
        Protected valide As Boolean
 
        ' data access method
        Public MustOverride Function getData() As Object()
 
        ' data verification method
        Protected Function checkData() As Integer
            ' verifies acquired data
            ' we need data
            valide = Not limites Is Nothing AndAlso Not coeffr Is Nothing AndAlso Not coeffn Is Nothing
            If Not valide Then Return 1
            ' we must have 3 arrays of the same size
            If valide Then valide = limites.Length = coeffr.Length AndAlso limites.Length = coeffn.Length
            If Not valide Then Return 2
            ' tables must be non-empty
            valide = limites.Length <> 0
            If Not valide Then Return 3
            ' each array must contain elements >=0 in ascending order
            valide = check(limites, limites.Length - 1) AndAlso check(coeffr, coeffr.Length) AndAlso check(coeffn, coeffn.Length)
            If Not valide Then Return 4
            ' all is good
            Return 0
        End Function
 
        ' checks the validity of an array's contents
        Protected Function check(ByRef tableau() As Decimal, ByVal n As Integer) As Boolean
            ' array must have its first n elements >=0 and in strictly ascending order
            If tableau(0) < 0 Then Return False
            For i As Integer = 1 To n - 1
                If tableau(i) <= tableau(i - 1) Then Return False
            Next
            ' it's good
            Return True
        End Function
    End Class
End Namespace

    La clase tiene los siguientes atributos protegidos:

    limits
    serie de límites de los tramos impositivos
    coeffr
    conjunto de coeficientes aplicados a la renta imponible
    coeffn
    tabla de coeficientes aplicados al número de acciones
    checked
    Booleano que indica si se han verificado los datos (límites, coeffr, coeffn)
    valid
    Booleano que indica si los datos (límites, coeffr, coeffn) son válidos

    La clase no tiene constructor. Tiene un método abstracto [getData] que las clases derivadas deben implementar. El propósito de este método es:

    • asignar valores a las tres matrices limits, coeffr, coeffn
    • lanzar una excepción si los datos no se han podido adquirir o si resultan ser inválidos.

    La clase proporciona los métodos protegidos [checkData] y [check] que verifican la validez de los atributos (limits, coeffr, coeffn). Esto libera a las clases derivadas de la necesidad de implementarlos. Simplemente tendrán que utilizarlos.

    La primera clase derivada que utilizaremos es la siguiente:

    
Imports System.Collections
Imports System
 
Namespace st.istia.univangers.fr
    Public Class impotsArray
        Inherits impotsData
 
        ' constructor with no arguments
        Public Sub New()
            ' initializing tables with constants
            limites = New Decimal() {4262D, 8382D, 14753D, 23888D, 38868D, 47932D, 0D}
            coeffr = New Decimal() {0D, 0.0683D, 0.1914D, 0.2826D, 0.3738D, 0.4262D, 0.4809D}
            coeffn = New Decimal() {0D, 291.09D, 1322.92D, 2668.39D, 4846.98D, 6883.66D, 9505.54D}
            checked = True
            valide = True
        End Sub
 
        ' builder with three input tables
        Public Sub New(ByRef limites() As Decimal, ByRef coeffr() As Decimal, ByRef coeffn() As Decimal)
            ' data storage
            Me.limites = limites
            Me.coeffr = coeffr
            Me.coeffn = coeffn
            checked = False
        End Sub
 
        Public Overrides Function getData() As Object()
            ' check data if necessary
            Dim erreur As Integer
            If Not checked Then erreur = checkData() : checked = True
            ' if invalid, then throw an exception
            If Not valide Then Throw New Exception("Les données des tranches d'impôts sont invalides (" + erreur.ToString + ")")
            ' otherwise we return the three tables
            Return New Object() {limites, coeffr, coeffn}
        End Function
    End Class
End Namespace

    Esta clase, llamada [impotsArray], tiene dos constructores:

    • un constructor sin argumentos que inicializa los atributos (limits, coeffr, coeffn) de la clase base con matrices hard-coded
    • un constructor que inicializa los atributos (limits, coeffr, coeffn) de la clase base con matrices que se le pasan como parámetros

    El método [getData], que permite a las clases externas recuperar las matrices (limits, coeffr, coeffn), simplemente verifica la validez de las tres matrices utilizando el método [checkData] de la clase base. Lanza una excepción si los datos no son válidos.

    6.1.5. Pruebas de clases de negocio y clases de acceso a datos

    Es importante incluir en una aplicación web sólo clases de negocio y de acceso a datos que hayan sido verificadas como correctas. De esta forma, la fase de depuración de la aplicación web puede centrarse en las capas de controlador y vista. Un programa de prueba podría tener el siguiente aspecto:

    
' options
Option Strict On
Option Explicit On 
 
' namespaces
Imports System
Imports Microsoft.VisualBasic
 
Namespace st.istia.univangers.fr
    Module test
        Sub Main()
            ' interactive tax calculator
            ' the user enters three data points on the keyboard: married nbEnfants salary
            ' the program then displays the tax payable
            Const syntaxe As String = "syntaxe : marié nbEnfants salaire" + ControlChars.Lf + "marié : o pour marié, n pour non marié" + ControlChars.Lf + "nbEnfants : nombre d'enfants" + ControlChars.Lf + "salaire : salaire annuel en F"
 
            ' tax object creation
            Dim objImpôt As impot = Nothing
            Try
                objImpôt = New impot(New impotsArray)
            Catch ex As Exception
                Console.Error.WriteLine(("L'erreur suivante s'est produite : " + ex.Message))
                Environment.Exit(1)
            End Try
            ' infinite loop
            Dim marié As String
            Dim nbEnfants As Integer
            Dim salaire As Long
            While True
                ' tax calculation parameters are requested
                Console.Out.Write("Paramètres du calcul de l'impôt au format marié nbEnfants salaire ou rien pour arrêter :")
                Dim paramètres As String = Console.In.ReadLine().Trim()
                ' anything to do?
                If paramètres Is Nothing OrElse paramètres = "" Then
                    Exit While
                End If
                ' check the number of arguments in the input line
                Dim erreur As Boolean = False
                Dim args As String() = paramètres.Split(Nothing)
                Dim nbParamètres As Integer = args.Length
                If nbParamètres <> 3 Then
                    Console.Error.WriteLine(syntaxe)
                    erreur = True
                End If
                ' checking the validity of parameters
                If Not erreur Then
                    ' married
                    marié = args(0).ToLower()
                    If marié <> "o" And marié <> "n" Then
                        erreur = True
                    End If
                    ' nbEnfants
                    Try
                        nbEnfants = Integer.Parse(args(1))
                        If nbEnfants < 0 Then
                            Throw New Exception
                        End If
                    Catch
                        erreur = True
                    End Try
                    ' salary
                    Try
                        salaire = Integer.Parse(args(2))
                        If salaire < 0 Then
                            Throw New Exception
                        End If
                    Catch
                        erreur = True
                    End Try
                End If
                ' if the parameters are correct - the tax is calculated
                If Not erreur Then
                    Console.Out.WriteLine(("impôt=" & objImpôt.calculer(marié = "o", nbEnfants, salaire) & " euro(s)"))
                Else
                    Console.Error.WriteLine(syntaxe)
                End If
            End While
        End Sub
    End Module
End Namespace

    La aplicación pide al usuario que introduzca los tres datos necesarios para calcular su impuesto:

    • estado civil: o para casado, n para soltero
    • número de niños
    • su salario anual

    El cálculo de impuestos se realiza mediante un objeto de tipo [impuesto] creado al iniciar la aplicación:

                objImpôt = New impot(New impotsArray)

    Como fuente de datos, utilizamos un objeto de tipo [impotsArray]. Se utiliza el constructor sin argumentos de esta clase, proporcionando las tres matrices (limites, coeffr, coeffn) con valores hard-coded. La creación de un objeto [impot] puede teóricamente lanzar una excepción porque, para crearse a sí mismo, el objeto solicitará los datos (limites, coeffr, coeffn) de su fuente de datos, que le fueron pasados como parámetro, y esta recuperación de datos puede lanzar una excepción. Sin embargo, en este caso, el método utilizado para obtener los datos (valores codificados) no puede provocar una excepción. No obstante, hemos dejado el tratamiento de la excepción para llamar la atención del lector sobre la posibilidad de que el objeto [impot] se construya incorrectamente.

    Protected lien As String

        ' retrieve context elements

        href = context.Items("href").ToString

            ' calculating the number of shares
            Dim nbParts As Decimal
            If marié Then
                nbParts = CDec(nbEnfants) / 2 + 2
            Else
                nbParts = CDec(nbEnfants) / 2 + 1
            End If
            If nbEnfants >= 3 Then
                nbParts += 0.5D
            End If
            ' calculation of taxable income & family quota
            Dim revenu As Decimal = 0.72D * salaire
            Dim QF As Decimal = revenu / nbParts
            ' tAX CALCULATION
            limites((limites.Length - 1)) = QF + 1
            Dim i As Integer = 0
            While QF > limites(i)
                i += 1
            End While

    Supongamos que un hilo está ejecutando el método anterior y es interrumpido. A continuación, otro subproceso ejecuta el método. ¿Cuáles son los riesgos? Para averiguarlo, añadimos el siguiente código:

    
            Dim impot As Long = CLng(revenu * coeffR(i) - nbParts * coeffN(i))
            ' wait 10 seconds
            Thread.Sleep(10000)
            Return impot

    El hilo 1, después de calcular el valor [impot1] de la variable local [impot], se interrumpe. A continuación, el hilo 2 ejecuta y calcula un nuevo valor [impot2] para la misma variable [impot] antes de ser interrumpido. El hilo 1 recupera el control. ¿Qué encuentra en la variable local [impot]? Como esta variable es local a un método, se almacena en una estructura de memoria llamada la pila. Esta pila forma parte del contexto del hilo, que se guarda cuando el hilo se suspende. Cuando el hilo 2 arranca, su contexto se configura con una nueva pila y, por tanto, con una nueva variable local [impot]. Cuando el hilo 2 se suspenda a su vez, su contexto también se guardará. Cuando se reinicia el hilo 1, se restaura su contexto, incluida su pila. Entonces recupera su variable local [impot] y no la del hilo 2. Por tanto, nos encontramos en una situación en la que no hay conflictos de acceso entre peticiones. Las pruebas realizadas con la pausa de 10 segundos descrita anteriormente confirmaron que las peticiones simultáneas producían efectivamente el resultado esperado.

    • construimos una respuesta destinada a los navegadores, que generalmente consta de documentos HTML

    Una aplicación web puede construirse para servir simultáneamente a distintos clientes, como navegadores y teléfonos móviles. Podemos entonces incluir un nuevo parámetro en cada petición indicando el tipo de cliente. Así, un navegador solicitará un cálculo de impuestos a través de una petición al URL http://machine/impots/main.aspx?client=navigateur&action=calcul, mientras que un teléfono móvil enviará una solicitud al URL http://machine/impots/main.aspx?client=mobile&action=calcul. La estructura MVC facilita el desarrollo de una aplicación de este tipo. Tiene la siguiente forma:

    El bloque [Business Classes, Data Access Classes] permanece inalterado. Esto se debe a que es un componente independiente del cliente. El bloque [Controller] sólo cambia ligeramente, pero debe tener en cuenta un nuevo parámetro en la solicitud: el parámetro [client], que indica el tipo de cliente que se gestiona. El bloque [Views] debe generar vistas para cada tipo de cliente. Puede merecer la pena tener en cuenta la presencia del parámetro [client] en la consulta desde la fase de diseño de la aplicación, incluso si el objetivo a corto o medio plazo se limita a los navegadores. Si más adelante la aplicación necesita soportar un nuevo tipo de cliente, sólo habrá que escribir vistas adaptadas a ese cliente.

        End Sub
 
        Public Overrides Function getdata() As Object()
            ' initializes the three limit tables, coeffr, coeffn from
            ' the contents of the [impots] table in the ODBC DSNimpots database
            ' limites, coeffr, coeffn are the three columns of this table
            ' can launch various exceptions
 
            Dim connectString As String = "DSN=" + DSNimpots + ";"         ' base connection chain
            Dim impotsConn As OdbcConnection = Nothing         ' the connection
            Dim sqlCommand As OdbcCommand = Nothing         ' the SQL command
            ' the SELECT query
            Dim selectCommand As String = "select limites,coeffr,coeffn from impots"
            ' tables to retrieve data
            Dim aLimites As New ArrayList
            Dim aCoeffR As New ArrayList
            Dim aCoeffN As New ArrayList
            Try

                impotsConn = New OdbcConnection(connectString)
                impotsConn.Open()
                ' create a command object
                sqlCommand = New OdbcCommand(selectCommand, impotsConn)
                ' execute the query
                Dim myReader As OdbcDataReader = sqlCommand.ExecuteReader()
                ' Using the recovered table
                While myReader.Read()
                    ' the data of the current line are put in the tables
                    aLimites.Add(myReader("limites"))
                    aCoeffR.Add(myReader("coeffr"))
                    aCoeffN.Add(myReader("coeffn"))
                End While
                ' freeing up resources
                myReader.Close()
                impotsConn.Close()
            Catch e As Exception
                Throw New Exception("Erreur d'accès à la base de données (" + e.Message + ")")
            End Try
            ' dynamic tables are placed in static tables
            Me.limites = New Decimal(aLimites.Count - 1) {}
            Me.coeffr = New Decimal(aLimites.Count - 1) {}
            Me.coeffn = New Decimal(aLimites.Count - 1) {}

            For i = 0 To aLimites.Count - 1

                coeffR(i) = Decimal.Parse(aCoeffR(i).ToString())
                coeffN(i) = Decimal.Parse(aCoeffN(i).ToString())

            If Not valide Then Throw New Exception("Les données des tranches d'impôts sont invalides (" + erreur.ToString + ")")
            ' otherwise we return the three tables
            Return New Object() {limites, coeffr, coeffn}
        End Function

    6.4.4. Los controladores [global.asax, main.aspx]

    Revisemos la arquitectura MVC de nuestra aplicación:

    El controlador [main.aspx] debe manejar tres acciones:

    • init: corresponde a la primera petición del cliente. El controlador muestra la vista [form.aspx]
    • calcular: corresponde a la solicitud de cálculo de impuestos. Si los datos del formulario de entrada son correctos, el impuesto se calcula utilizando la clase de negocio [impotsODBC]. El controlador devuelve al cliente la vista [simulations.aspx] con el resultado de la simulación actual más todas las anteriores. Si los datos del formulario de entrada son incorrectos, el controlador devuelve la vista [erreurs.aspx] con la lista de errores y un enlace para volver al formulario.
    • devolver: corresponde a volver al formulario después de un error. El controlador muestra la vista [form.aspx] tal y como estaba validada antes del error.

    6.5. Conclusión

    Los ejemplos anteriores han demostrado, en un escenario concreto, mecanismos utilizados habitualmente en el desarrollo web. Hemos utilizado sistemáticamente la arquitectura MVC por su valor didáctico. Podríamos haber tratado estos mismos ejemplos de forma diferente y quizás más sencilla sin esta arquitectura. Sin embargo, ofrece ventajas significativas en cuanto la aplicación se vuelve algo compleja con múltiples páginas.

    Podríamos continuar nuestros ejemplos de varias maneras. He aquí algunos:

    • Es posible que el usuario desee guardar sus simulaciones a lo largo del tiempo. Podría realizar simulaciones el día D y recuperarlas el día D+3, por ejemplo. Una posible solución a este problema es el uso de cookies. Sabemos que el testigo de sesión entre el servidor y un cliente se transmite a través de este mecanismo. También podríamos utilizar este mecanismo para transmitir las simulaciones entre el cliente y el servidor.
      • Al mismo tiempo que el servidor envía la página que contiene los resultados de la simulación, envía una cookie en sus cabeceras HTTP que contiene una cadena que representa las simulaciones. Dado que éstas se encuentran en un objeto [ArrayList], este objeto debe convertirse en una [Cadena]. El servidor establecería un tiempo de vida para la cookie, por ejemplo 30 días.
      • El navegador cliente almacena las cookies recibidas en un archivo y las devuelve cada vez que realiza una petición a un servidor que las envió, siempre que sigan siendo válidas (no se haya superado el tiempo de vida). El servidor recibirá una cadena de caracteres [String] para las simulaciones, que deberá convertir en un objeto [ArrayList].

    Las cookies son gestionadas por [Response.Cookies] cuando se envían al cliente y por [Request.Cookies] cuando se reciben en el servidor.

    • El mecanismo descrito puede consumir muchos recursos si hay un gran número de simulaciones. Además, es habitual que un usuario borre periódicamente todas sus cookies, aunque permita que su navegador las utilice. Así que, tarde o temprano, las cookies de simulación se perderán. Por lo tanto, es posible que queramos almacenarlas en el servidor en lugar de en el cliente, en una base de datos, por ejemplo. Para vincular las simulaciones a un usuario concreto, la aplicación podría comenzar con una fase de autenticación que requiera un nombre de usuario y una contraseña, que a su vez se almacenan en una base de datos o en cualquier otro tipo de repositorio de datos.
    • También podríamos querer asegurar el funcionamiento de nuestra aplicación. Actualmente hace dos suposiciones:
      1. el usuario siempre pasa por el controlador [main.aspx]
      2. y en ese caso, siempre utiliza las acciones disponibles en la página que le fue enviada

    ¿Qué ocurre, por ejemplo, si el usuario solicita directamente el URL [http://localhost/impots4/formulaire.aspx]? Este escenario es poco probable, ya que el usuario desconoce este URL. Sin embargo, debe tenerse en cuenta. Puede ser gestionado por el controlador de la aplicación [global.asax], que procesa todas las peticiones realizadas a la aplicación. Así, puede verificar que el recurso solicitado es efectivamente [main.aspx].

    Un escenario más probable es que un usuario no utilice las acciones disponibles en la página que el servidor le envió. Por ejemplo, ¿qué ocurre si el usuario solicita directamente el URL [http://localhost/impots4/main.aspx?action=retour] sin rellenar primero el formulario? Intentémoslo. Obtenemos la siguiente respuesta:

    El servidor se bloquea. Esto es normal. Para la acción [return], el controlador espera encontrar un objeto [NameValueCollection] en la sesión que represente los valores del formulario que necesita mostrar. No los encuentra. El mecanismo del controlador proporciona una solución elegante a este problema. Para cada petición, el controlador [main.aspx] puede verificar que la acción solicitada es efectivamente una de las acciones de la página enviada previamente al usuario. Podemos utilizar el siguiente mecanismo:

    • Antes de enviar su respuesta al cliente, el controlador almacena la información que identifica esta página en la sesión del cliente
    • cuando recibe una nueva solicitud del cliente, comprueba que la acción solicitada pertenece efectivamente a la última página enviada a ese cliente
    • La información que vincula las páginas y las acciones permitidas en esas páginas pueden introducirse en el archivo de configuración [web.config] de la aplicación.
    • La experiencia demuestra que los controladores de aplicaciones comparten una amplia base común y que es posible construir un controlador genérico, cuya especialización para una aplicación determinada se gestiona a través de un archivo de configuración. Este es el enfoque adoptado, por ejemplo, por la herramienta [Struts] en el ámbito de la programación web en Java.
